# قائمة التنفيذ والإطلاق لموقع مطعم الغدير

تُستخدم هذه القائمة مع [قاعدة المعرفة](knowledge-base-ar.md) و[دليل القائمة](menu-catalog-ar.md). أبقِ مربعات الاختبار الميداني مفتوحة حتى تحصل على نتيجة من نسخة الاستضافة وعلى بيانات المالك النهائية.

## ١. اعتماد البيانات والهوية

- [ ] طابق اسم «مطعم الغدير» وشكل الشعار مع اللافتة أو الملف الرسمي. اختر التهجئة اللاتينية المعتمدة لاستخدامها اسماً بديلاً في بيانات التعريف والبحث.
- [ ] اعتمد الرقم `0501083083` لحساب واتساب وتأكد من الاستقبال. إذا كان رقم المكالمات مختلفاً، حدّثه وحده.
- [ ] أكد ساعات العمل لجميع أيام الأسبوع وأضف مواعيد رمضان والإجازات عند الحاجة.
- [ ] أكد وجود قسم الأفراد وقسم العائلات والاستلام والتوصيل المجاني. دوّن أي أحياء أو ساعات أو حد أدنى للخدمة.
- [ ] ثبت رابط خريطة مدخل الفرع الصحيح في حي النهضة بحفر الباطن والعنوان الوطني أو معلومات الشارع إذا توفرت. اختبر الاتجاهات من الهاتف.
- [ ] سلّم روابط حسابات التواصل التابعة للغدير. اختبر الحسابات قبل تفعيل أيقوناتها.
- [ ] راجع أسماء الأصناف والأقسام والأسعار في الملحق. اعتمد المقاس الخامس لمشكل المشويات وسعر بيض الجبنة وسعر المشروب الغازي الصغير، وراجع الرقم الإضافي في عمود الفطور والسطر الفخاري المكرر.
- [ ] اعتمد الأوصاف والصور بصرياً. أضف معلومات المكونات أو الحساسية أو الحصص فقط عند تأكيدها من المطعم.
- [ ] اعتمد نطاق الإنتاج واختر الشكل الأساسي للرابط باستخدام HTTPS. اربط نطاقاً باسم المطعم حيث يكون ذلك مناسباً لهويته.

## ٢. تجهيز المصدر والبناء المحلي

- [ ] فك ملف الموقع في مجلد عمل. استخدم Node.js 20.19.0 أو أحدث، وفق إعداد المشروع. ثبّت الحزم بالأمر `npm ci`.
- [ ] عدّل بيانات العمل والروابط في `src/config.js`، والقائمة في `src/menu-data.json`، والصور في `public/images/`. اجعل أسماء صور الأصناف تطابق معرّفاتها وثبّت عناوينها عند تعديل النص.
- [ ] شغّل `npm run dev` وراجع الرئيسية، قصتنا، المنيو، الفروع، التواصل، وصفحة صنف ذات سعر واحد وصفحة صنف متعدد الأسعار.
- [ ] شغّل `npm run build` و`npm run verify`. يجب أن يحتوي `dist/` على الصفحات والأصول الثابتة.
- [ ] شغّل `npm run preview` لاختبار نسخة البناء. افتح صفحة صنف مباشرة وحدّثها، ثم جرّب رابطاً غير موجود.
- [ ] عند تجديد صور المنيو، اضغط الصور إلى WebP مناسب لعرض البطاقة والتفاصيل. أضف أبعاد العرض والارتفاع في HTML وتأكد من القراءة البصرية للصورة والاسم على الجوال.

## ٤. SEO قبل النشر

- [ ] أجرِ بناء الإنتاج على النطاق النهائي. في Bash شغّل `SITE_URL=https://your-domain.example npm run build`. في PowerShell اضبط `$env:SITE_URL = "https://your-domain.example"` ثم شغّل `npm run build`. استبدل المثال بعنوان HTTPS الموثق.
- [ ] راجع `dist/robots.txt` و`dist/sitemap.xml` ووسم `canonical` في الرئيسية وفي صنف داخلي. يجب أن تستخدم جميعها الشكل الأساسي نفسه للنطاق. نسخة البناء التي لا تحدد `SITE_URL` هي للمراجعة وتطلب عدم الفهرسة.
- [ ] راجع HTML الأصلي لصفحات الرئيسية والمنيو والتفاصيل. تظهر لغة الصفحة واتجاهها وعنوانها ووصفها والمحتوى المهم وروابط الأصناف قبل تنفيذ JavaScript.
- [ ] راجع عدم تكرار عناوين الصفحات والأوصاف بشكل غير مبرر. افتح معاينة مشاركة الصفحة للتحقق من عنوان المشاركة وصورتها.
- [ ] افحص بيانات `Restaurant` وعناوين المسارات وأسعار الأصناف بأداة فحص البيانات المنظمة. تحقق من الاسم والمدينة والساعات والهاتف. أضف الإحداثيات أو روابط الحسابات عند تأكيدها فقط. [اختبار النتائج المنسقة](https://search.google.com/test/rich-results) · [مواصفات بيانات النشاط](https://developers.google.com/search/docs/appearance/structured-data/local-business)
- [ ] راجع مسار خطأ حقيقي تحت النطاق، ولا تستخدم إعادة كتابة شاملة تعيد الصفحة الرئيسية مع حالة `200` لكل رابط غير موجود. [أخطاء HTTP والفهرسة](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes)

## ٥. نشر الملفات الثابتة

- [ ] اختر مزود استضافة ثابتة يدعم ربط نطاق وشهادة TLS وفهرس المجلدات. في رفع الملفات يدوياً، ارفع **محتويات** `dist/` إلى جذر الموقع. في البناء من مستودع، اجعل أمر البناء `npm run build` ومجلد النشر `dist` وأدخل `SITE_URL` في إعدادات بيئة البناء.
- [ ] إذا اخترت Cloudflare Pages، ارفع مجلد `dist/` عبر Direct Upload، أو اضغط محتوياته بحيث يكون `index.html` في جذر ملف الرفع. يخدم وجود `404.html` في الجذر صفحة الخطأ المخصصة. [الرفع المباشر](https://developers.cloudflare.com/pages/get-started/direct-upload/) · [خدمة الصفحات](https://developers.cloudflare.com/pages/configuration/serving-pages/)
- [ ] اربط النطاق من لوحة الاستضافة ثم أدخل سجلات DNS التي يحددها مزودها. اختبر HTTPS وانتقل من النطاق البديل إلى النطاق الأساسي بتحويل دائم حسب إعداد الاستضافة.
- [ ] تأكد من خدمة `/menu/` و`/menu/<slug>/` مباشرة من ملفات `index.html` المولّدة في مجلداتها، ومن سلامة `/robots.txt` و`/sitemap.xml` والصور. اضبط `404.html` بحسب تعليمات المضيف.
- [ ] عند النشر في مجلد فرعي، استخدم عنوانه الكامل في `SITE_URL` لينتج البناء مسارات أصول متوافقة. قواعد `robots.txt` تُقرأ من جذر النطاق، فأضف إشارة خريطة الموقع في الجذر عندما تملك صلاحية ذلك. [موقع ملف robots.txt](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt)
- [ ] افحص عبر نافذة خاصة ومن اتصال مختلف. جرّب الصفحة الرئيسية والمنيو وثلاثة أصناف والفروع والتواصل وواتساب وصفحة غير موجودة.
- [ ] احتفظ بآخر بناء ناجح أو إصدار مصدر معروف كي يمكن إعادة نشره إذا ظهر خطأ.

## ٦. ما بعد الإطلاق

- [ ] تحقّق من ملكية النطاق في Search Console وأرسل `sitemap.xml`. افحص الرئيسية والمنيو وصفحة صنف للتحقق من إمكانية الزحف ثم اطلب الفهرسة للصفحات الأساسية. [بدء استخدام Search Console](https://developers.google.com/search/docs/monitor-debug/search-console-start) · [إرسال خريطة الموقع](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- [ ] طالب بملف نشاط مطعم الغدير في Google أو اربطه بالحساب المالك بعد توثيق الموقع الفعلي. حدّث الاسم والعنوان والفئة والرقم والساعات ورابطي الموقع والمنيو والصور الحقيقية. [تحسين ظهور النشاط محلياً](https://support.google.com/business/answer/7091)
- [ ] راقب تقارير الفهرسة والأداء. جرّب «مطعم الغدير حفر الباطن» و`Al Ghadeer Restaurant Hafar Al Batin` والتهجئة الرسمية. يتأثر الترتيب بالمنافسة وموضع الباحث وإشارات النشاط ويحتاج إلى متابعة بعد الإطلاق.
- [ ] عند تعديل الأسعار أو الساعات أو الروابط، حدّث المصدر وأعد بناء الإنتاج وتحقق من الموقع الفعلي. حافظ على مطابقة بيانات المطعم بين الموقع وملف النشاط.
